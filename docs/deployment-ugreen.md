# Развёртывание на UGREEN NAS

Инструкция для UGREEN DXP6800 Pro с UGOS Pro. Подойдёт и другой хост с Docker Compose.

## Токен ZenMoney

Сервис не получает токен сам: он берёт готовый токен доступа из `API_TOKEN`. Токен можно получить через OAuth2 в библиотеке `zenmoney_lib`, как в её `examples/fetch_diff.py`:

```python
from zenmoney import ZenmoneyOAuth2

oauth = ZenmoneyOAuth2(consumer_key=..., consumer_secret=..., username=..., password=...)
print(oauth.token.access_token)
```

Логин и пароль на NAS не нужны, там хранится только токен. Запрос к API описан в [архитектуре](architecture.md#запрос-к-api), менять его настройками не требуется.

Когда срок токена истечёт, запросы начнут завершаться ошибкой 401. Порядок замены описан в [эксплуатации](operations.md#замена-токена).

## Каталог для копий

Копии должны лежать на HDD-пуле, а не внутри контейнера. Контейнер работает от UID 10001, поэтому этому пользователю нужно право записи в папку.

Подключитесь к NAS по SSH (включается в настройках UGOS Pro) и выполните команды, подставив свой путь:

```bash
sudo mkdir -p /volume1/backups/zenmoney
```

```bash
sudo chown 10001:10001 /volume1/backups/zenmoney
```

Копии содержат всю финансовую историю, поэтому закройте папку от других пользователей NAS:

```bash
sudo chmod 750 /volume1/backups/zenmoney
```

Если не создать папку заранее, Docker создаст её от root, и запись завершится ошибкой `Permission denied`.

После `chown` файлы принадлежат UID 10001. Чтобы открывать копии по сети от своего пользователя, настройте доступ к этой папке отдельно.

## Настройка `.env`

Скопируйте весь репозиторий на NAS: образ собирается из него, а не только из каталога `deploy`. Затем создайте файл настроек:

```bash
cp deploy/.env.example deploy/.env
```

Заполните `API_TOKEN` и `BACKUP_HOST_DIR`. Ограничьте доступ к файлу, в нём лежит секрет:

```bash
chmod 600 deploy/.env
```

Описание остальных переменных есть в [README](../README.md#настройки).

## Запуск через SSH

Этот способ рекомендуется. Перейдите в каталог `deploy` и выполните:

```bash
docker compose up -d --build
```

Если на NAS установлен `make`, из корня репозитория достаточно `make up`.

## Запуск через приложение Docker в UGOS

В приложении Docker создайте проект и укажите каталог `deploy` с файлом `compose.yaml`. Compose собирает образ из родительского каталога, поэтому на NAS должен лежать весь репозиторий.

Работа такого проекта в интерфейсе UGOS не проверялась. Если сборка не запустится, используйте запуск через SSH. Контейнером потом можно управлять и из приложения.

## Проверка

1. `docker compose logs --tail=100` показывает `Scheduled daily backup at 03:00`.
2. При пустой папке копия создаётся сразу после старта: в логах есть `Backup saved`.
3. В папке на HDD лежат `zenmoney_<дата>_<время>.json` и `.json.sha256`.
4. Контрольная сумма сходится (выполнять в папке с копиями):

```bash
sha256sum -c zenmoney_*.sha256
```

5. После перезагрузки NAS контейнер запускается сам благодаря `restart: unless-stopped`, если служба Docker стартует вместе с системой. Проверить состояние можно так:

```bash
docker compose ps
```

Контейнер, остановленный вручную через `docker stop`, после перезагрузки не запустится: так работает `unless-stopped`.
