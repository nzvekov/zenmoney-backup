# Эксплуатация

Команды `docker compose` выполняются в каталоге `deploy`. Из корня репозитория можно использовать `make`.

## Ручное создание копии

Контейнер останавливать не нужно:

```bash
docker compose exec zenmoney-backup zenmoney-backup --once
```

То же самое делает `make backup`.

Ручной запуск создаёт копию, даже если копия за сегодня уже есть. Код выхода: `0` при успехе, `1` при ошибке или если уже идёт другой бэкап, `2` при ошибке настроек.

## Логи

```bash
docker compose logs -f --tail=100
```

Размер логов ограничен: 3 файла по 10 МБ. Токен в логи не попадает.

Нормальный запуск выглядит так:

```
Backup started
HTTP status=200 response_time=4.2s
Downloaded bytes=52428800 download_time=18.7s
JSON validation passed
Backup saved path=/backups/zenmoney_2026-11-04_03-00-00.json bytes=52428800 sha256=...
Rotation finished: removed=1 remaining=30 retain=30
Job finished total_time=21.3s
```

При неудачном запуске в логе есть строка `Backup failed: <причина>`. Следующая за ней строка APScheduler `executed successfully` означает только то, что задание завершилось без необработанного исключения.

## Расписание

Измените `BACKUP_HOUR`, `BACKUP_MINUTE` или `TZ` в `deploy/.env` и пересоздайте контейнер. Команда `restart` новые настройки не применит.

```bash
docker compose up -d
```

Как работает расписание:

- **Одна копия в день:** плановый запуск пропускается, если копия за сегодня уже есть, в том числе созданная вручную.
- **Пропущенный запуск:** при старте сервис проверяет, есть ли копия новее последнего планового времени. Если нет, он сразу делает копию. Отключается через `CATCH_UP_MISSED=false`.
- **Неудачный запуск:** после исчерпания повторов следующая попытка будет по расписанию или при перезапуске контейнера. Чтобы не ждать, сделайте копию вручную.

## Количество копий

Измените `RETENTION_COUNT` в `deploy/.env` и выполните `docker compose up -d`. Лишние копии удалятся после следующего успешного бэкапа.

Новая копия записывается до удаления старых, поэтому свободного места нужно на N+1 копий.

## Восстановление данных

Копия содержит ответ API без изменений: полный снимок данных аккаунта на момент запроса.

Сначала проверьте целостность (в папке с копиями):

```bash
sha256sum -c zenmoney_2026-11-04_03-00-00.json.sha256
```

Посмотреть состав копии можно через `jq`, если он установлен:

```bash
jq 'to_entries | map({key, count: (.value | if type == "array" then length else 1 end)})' zenmoney_2026-11-04_03-00-00.json
```

Сервис не загружает данные обратно в ZenMoney. Копия подходит для просмотра, анализа и ручного переноса. Для обратной записи нужен отдельный сценарий, и его стоит сначала проверить на тестовом аккаунте.

Копии на том же NAS не заменяют внешнюю копию: при отказе пула пропадут и они.

## Замена токена

Запишите новый `API_TOKEN` в `deploy/.env` и пересоздайте контейнер:

```bash
docker compose up -d
```

## Обновление сервиса

Обновите файлы репозитория на NAS и пересоберите образ. Копии лежат вне контейнера и не затрагиваются:

```bash
docker compose up -d --build
```

## Типичные ошибки

| Сообщение в логах | Причина | Что сделать |
|---|---|---|
| `HTTP 401: authorization failed` или `HTTP 403: ...` | Токен неверный или истёк | [Заменить токен](#замена-токена) |
| `All N attempts failed, last error: HTTP 429` | API ограничивает частоту запросов | Подождать, копия будет сделана при следующем запуске |
| `All N attempts failed, last error: HTTP 5xx` | Сбой на стороне API | Подождать, при необходимости сделать копию вручную |
| `ConnectError`, `ConnectTimeout` | Нет сети или DNS на NAS | Проверить сеть NAS и доступ к `api.zenmoney.ru` |
| `ReadTimeout` | Сервер долго формирует ответ | Увеличить `API_TIMEOUT`, например до 300 |
| `Invalid JSON` | Ответ оборван или повреждён | Обычно проходит при повторе; если нет, проверить API вручную |
| `JSON has no top-level serverTimestamp` | Вместо данных пришёл другой JSON | Проверить `API_URL` и токен |
| `Response exceeds MAX_BACKUP_BYTES` | Ответ больше предела | Увеличить `MAX_BACKUP_BYTES`, проверить место на диске |
| `not enough disk space` | Закончилось место | Освободить место или уменьшить `RETENTION_COUNT` |
| `disk error: ... Permission denied` | Нет прав у UID 10001 | Выполнить [`chown`](deployment-ugreen.md#каталог-для-копий) для папки |
| `Another backup is running, skipping` | Уже идёт другой бэкап | Дождаться окончания |
| `Configuration error: ...` | Ошибка в `.env`, контейнер перезапускается | Исправить указанную переменную |
| `Rotation: could not remove ...` | Не удалось удалить старую копию | Проверить права. Копия будет удалена при следующей ротации |

Сервис не отправляет оповещений о сбоях, поэтому периодически проверяйте, что новые копии появляются. Подключить уведомления можно по [инструкции](architecture.md#уведомления).
